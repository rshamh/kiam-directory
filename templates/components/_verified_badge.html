{% comment %} VerifiedBadge — "Verified", and what that does and does not mean. {% include "components/_verified_badge.html" with practitioner=practitioner %} The claim is narrow on purpose: the required documents were checked and remain in date. It is NOT a competence, quality or outcome claim, and the copy must never drift towards one — no "approved", no "trusted", no "recommended", no tick that reads as an endorsement. The link to /how-verification-works/ is part of the badge rather than an optional extra, because docs/verification-policy.md requires the limits of the claim to be one click away from wherever the claim appears. Absence is meaningful: a published listing whose insurance lapsed loses the badge automatically overnight and renders nothing here. There is deliberately no "not verified" state — a badge nobody can set by hand also should not be a label that shames the listing it is missing from. `practitioner.is_verified` and `credentials_checked_at` are COMPUTED (directory/services/verification.py). Never rendered from anything else. **THE DATE MOVED INTO THE PANEL, it did not go away.** The badge used to read "Credentials checked 30 July 2026" on its face. On a register of twenty rows that is four lines in a 232px rail where the reference design spends one, and the date is not the thing a visitor is scanning for — "is this one checked" is. It is still one hover or one focus away, and still on the profile page, because a freshness claim with no date behind it is not a freshness claim. WHAT THE PANEL SAYS IS WHAT IS ACTUALLY ENFORCED. `verification.BASE_REQUIRED` is photo ID, regulator/professional-body registration, qualification and professional indemnity insurance, plus prescriber status for a prescriber. The panel names those and nothing else — no DBS, which is a separate gate and not one of the badge's required checks. **THE PANEL IS HIDDEN BY CSS AND SHOWN BY A CLASS — never the other way round.** It was `x-cloak x-show="open"`, which hides by having Alpine write `display: none` onto an element the stylesheet leaves visible. That fails OPEN: anything that stops Alpine applying `x-show` to a node leaves the panel on the screen. It did, and reliably — after an htmx filter swap, **11 of the 12** rows rendered with their explanation panel hanging open, `x-cloak` already stripped and no inline `display` ever written. Alpine's MutationObserver picked the swapped-in nodes up far enough to remove the cloak and not far enough to run the directive. So the default now lives in the stylesheet (`.dir-verified__note { display: none }`) and Alpine only ever ADDS `is-open`. Every failure mode — script off, Alpine not loaded, an htmx swap Alpine misses, a JS error earlier on the page — now leaves the panel closed instead of open, which is the same fail-closed reasoning as the antivirus backend and the POM dictionary. The `aria-describedby` behaviour is unchanged: a closed panel is still `display: none`, so the description still resolves to nothing rather than making a reader hear twelve explanations nobody asked for. HOVER IS NOT THE ONLY WAY IN (WCAG 1.4.13, and 2.1.1 before it): * The trigger is a real LINK to the full explanation, so the panel is supplementary. With JavaScript off the class is never added and the panel simply does not appear; the link still works. That is the same choice the Phase 5b hint row and the speciality filter box made. * `@focusin` opens it, so a keyboard user gets the same panel a mouse user does. * `@keydown.escape` dismisses it without moving focus. * It stays open while the pointer is inside the badge, because the handlers are on the badge and the panel is inside it. * **Nothing interactive lives in the panel.** The reference design repeats "How verification works" as a link inside it; that would be the same destination as the trigger two tab stops away, twenty times on a results page, and a keyboard user would have to tab INTO a hover panel to reach it. The trigger is the link. `aria-describedby` points at the panel, so when it is open a screen reader reads the explanation as the link's description — and when it is closed the panel is `display: none` and the description resolves to nothing, which is correct rather than a bug: the reader is not made to hear twenty explanations they did not ask for.
