## 1. Install and wiring

The package is a plain Django app. No models, no migrations, no URLs.

```python
INSTALLED_APPS = [..., "kiam_ui", ...]
```

Four context processors are **required** — the package's templates fail or degrade silently
without them:

| Processor | Why it is required |
|---|---|
| `django.template.context_processors.request` | `base.html` builds the default canonical and `og:url` from `request` |
| `django.template.context_processors.i18n` | `base.html` and most partials `{% load i18n %}` |
| `kiam_ui.context_processors.accessibility` | exposes `a11y` — the whitelisted display prefs applied to `<html>` server-side, before first paint |
| `kiam_ui.context_processors.kiam_ui` | exposes `kiam_ui` — the resolved `KIAM_UI` settings dict the chrome reads |

`kiam_ui.context_processors.accessibility` reads a `kiam_a11y` cookie and **validates** it before
reflecting it into HTML attributes (font size is whitelisted against
`{"default", "large", "larger"}`, the rest are coerced to bool). The cookie is deliberately
readable by all three Kiam sites — see `docs/multi-project-architecture.md` §4.

### Template tag library

One library, `{% load kiam_ui %}`, containing one filter:

- **`kiam_url`** — resolves a configured link that may be a URL *name* (`"accounts:login"`) or a
  literal path/URL (`/sign-in/`, `https://…`, `#…`, `mailto:`, `tel:`). Tries `reverse()` first
  and falls back to the literal. Used by the header for the `AUTH` links, so a site can configure
  either form.

### Management command

```bash
python manage.py kiam_ui_vendor          # -> build/kiam-ui/{css,templates}
```

Copies the package's **CSS source** and **templates** to a path a Tailwind build can reach.
Required because Tailwind resolves `@source`/`@import` relative to the CSS file and cannot see
into site-packages — a utility class used *only* inside a packaged template is purged from the
production build, silently. The command wipes the destination first, so an upstream deletion
propagates. `build/` is **build output**: gitignored, re-run after every pin bump, and kept
outside `static/` so `collectstatic` cannot publish the package's Django templates at `/static/`.

before first paint.

## 3. The `KIAM_UI` settings dict

Every key is optional. Defaults are **brand-family neutral** — a site that forgets to configure
the package gets empty chrome, never another site's contact details. Read from
`kiam_ui/conf.py::DEFAULTS`.

| Key | Default | What it does |
|---|---|---|
| `SITE_NAME` | `"Kiam"` | `<title>` fallback, `og:site_name`, the wordmark, and the clinic name inside the emergency disclaimer copy |
| `SITE_KIND` | `"main"` | emits `site-header--<kind>`; set to `"directory"` here so an override can branch without sniffing the hostname |
| `BRAND_PREFIX` / `BRAND_ACCENT` | `None` | wordmark split, rendered `"<prefix> <accent>"` with the accent in brand green. Derived from `SITE_NAME` on the first space when unset |
| `HOME_URL` | `"/"` | brand lockup link target |
| `NAV_ITEMS` | `[]` | drives the desktop nav **and** the mobile drawer from one list. Accepts a dotted path to `callable(request)` |
| `PRIMARY_CTA` | `None` | `{"label", "url"}`; renders the header CTA button |
| `COMPACT_CTA_LABEL` | `_("Book")` | short CTA below the header breakpoint |
| `SHOW_DISCLAIMER_BAR` | `True` | header layer 1 |
| `DISCLAIMER_TEMPLATE` | `None` | a partial rendered *in place of* the packaged emergency copy. Marquee, landmark and pause control are kept either way |
| `CONTACT` | `{}` | `street`, `locality`, `region`, `postcode`, `phone`, `phone_e164`, `email`, `whatsapp`. Anything missing is simply not rendered. Accepts a dotted path |
| `URLS` | `{}` | the other Kiam sites. **Read by no packaged template at v1.0.1** — see Gap 5 |
| `AUTH` | `None` | `{"LOGIN_URL", "LOGOUT_URL", "DASHBOARD_URL", "DASHBOARD_LABEL"}`. `None` renders no auth controls at all |
| `FOOTER` | `{}` | `TAGLINE`, `NOTE`, `COLUMNS`, `LEGAL_NAME`, `COMPANY_NUMBER`, `LEGAL_LINKS`. Accepts a dotted path |
| `SHOW_LANGUAGE_SWITCHER` | `True` | **must be `False` here** — see Gap 1 |

`NAV_ITEMS`, `CONTACT` and `FOOTER` are the three keys that accept a **dotted path to a
callable taking `request`** (`kiam_ui.conf.RESOLVABLE`). That is how the main site builds its nav
from the live Wagtail tree. This repo has no page tree, so literal values are correct — except
where a nav item must depend on the request.

### Nav item shape

```python
{"label": "Home", "url": "/"}                                  # plain link
{"label": "Kiam Clinic", "url": "https://kiamclinic.com/",     # link to another site
 "external": True, "aria_label": "…"}
{"label": "Browse", "key": "browse", "panel_label": "…",       # mega menu
 "items": [{"icon", "label", "title", "url", "description"}, …],
 "footer": {"url", "label", "desc"},
 "drawer_lead": {"label", "url"},
 "drawer_items": [{"title", "url"}, …],                        # defaults to `items`
 "fallback_url": "/browse/"}
```

`conf._nav_item()` normalises every key the header reads, so a consumer writes the minimum. A
mega menu whose `items` is empty **degrades to a plain link** at `fallback_url` — an empty
dropdown is a dead end.

### Slot convention

`{% include %}` has no slot mechanism, so wrapper components take their inner content as
`*_template` — **the path of a partial rendered at the slot position, in the caller's context**.
`body` / `actions` accept pre-rendered *safe* HTML as the alternative. Prefer the template form.

### Heading levels are a parameter, not a style

`disclaimer.html`, `form_success.html` and `section_head.html` all take a `heading_level`. Set it
so the page's heading order stays sequential — **never** for its size, which is fixed by the
class. This is load-bearing for golden rule #3 and for the a11y-reviewer gate.

## 5. Colour tokens and the documented WCAG pairings

Tokens are CSS custom properties on `:root`, shipped in the compiled `kiam-ui.css`. **Reference
them; do not restate their values in this repo.**

**Brand base:** `--green-900` `--green-800` `--green-600` `--green-500` `--green-100`
`--mint-200` `--mint-100` `--mint-50` · `--blue-700` `--blue-500` · `--amber-500` `--amber-100` ·
`--slate-900` `--slate-700` `--slate-400` · `--line` `--white`

**Semantic aliases (use these, not the base swatches):** `--surface-page` `--surface-card`
`--surface-sunken` `--surface-sunken-deep` `--surface-inverse` · `--text-primary`
`--text-heading` `--text-secondary` `--text-faint` `--amber-text` `--text-on-brand` `--text-link`
`--text-link-hover` · `--brand-primary` `--brand-primary-dark` `--brand-secondary`
`--brand-accent-soft` · `--border-default` `--border-hover` `--control-border` · `--focus-ring`

**Other token families:** typography (`--font-sans` `--font-serif-display`, `--weight-*`,
`--text-display-*` / `--text-title-*` / `--text-body-*` / `--text-caption` / `--text-eyebrow`,
`--line-height-*`, `--letter-*`), spacing (`--space-1` … `--space-24`, `--radius-sm|md|lg|xl|pill`,
`--container-max`, `--container-pad`), effects (`--shadow-card` `--shadow-soft` `--shadow-float`
`--shadow-btn-primary*`, `--ease-brand`, `--duration-fast|base|slow|reveal`).

### Contrast pairings the package documents in its own CSS

These are the AA fixes kiam-ui applied and recorded in comments. They are the rules that matter
when composing directory-specific components:

| Rule | Why |
|---|---|
| **Faint text uses `--text-faint`, never `--slate-400`.** | The raw swatch is ~2.9:1 on white/mint — fails AA for text. The alias is darkened to ≥4.6:1 on white, `--mint-50` and `--mint-100`. The raw swatch stays for decorative use only. |
| **Amber text uses `--amber-text`, never `--amber-500`.** | `--amber-500` on `--amber-100` is 2.5:1. The alias reaches 4.85:1. |
| **Form controls use `--control-border`, never `--line`.** | WCAG 1.4.11 needs 3:1 for control boundaries; `--line` is 1.2:1 — fine for card hairlines, invisible as an input edge. `--control-border` is ~3.2:1 on mint/white. |
| **White text on a green gradient anchors to `--brand-primary` (green-600), not `--green-500`.** | The teal end gives white only ~4.1:1. Anchored, white passes at ≥5.25:1 across the whole button. The teal→green motif is kept for *large* white text on banners. |
| **`.ds-eyebrow--inverse` is a white pill, not a white-on-wash label.** | White on a 16% white wash over the green gradient measures 3.9:1. The pill treatment measures 6.3:1 on green, 8.5:1 on blue. |
| **CTA banner body copy anchors its light gradient stop to green-600 / blue-700.** | green-500 / blue-500 dropped `.ds-cta__desc` below 4.5:1. |
| **Footer link text on `--green-900` uses `--mint-100`.** | ≥8:1. |
| **The green focus ring is replaced with a light ring on deep-forest surfaces.** | The global ring is too low-contrast there. |

High-contrast mode (`html[data-contrast="high"]`) re-darkens `--text-faint`, widens the focus
outline to 4px, and underlines links inside `.prose`, `.ds-consent__label` and
`.ds-disclaimer__content`. Any directory-specific component that renders links in prose should
pick up one of those containers or add its own rule.

### CSS class vocabulary

`kiam-ui` owns the `ds-*` component vocabulary (`ds-card`, `ds-pill`, `ds-field`, `ds-control`,
`ds-icon`, `ds-cta`, `ds-disclaimer`, `ds-section-head`, `ds-breadcrumb`, `ds-form-card`,
`ds-form-success`, `ds-consent`, `ds-ticklist`, `ds-linkrow`, `ds-panel--blue`), the chrome
(`site-header`, `header-*`, `nav-*`, `mega-*`, `mobile-*`, `site-footer`, `footer-*`,
`disclaimer-bar*`, `a11y-*`), and the primitives `btn`, `btn-primary|ghost|light|sm|block`,
`brand*`, `container`, `section`, `skip-link`, `sr-only`.

**Directory-specific components must not redefine any of those.** Ours are namespaced `dir-*`.

## 6. Tailwind integration

Two layers, and the order matters:

1. **`kiam-ui.css`** — plain, pre-compiled, unlayered. Linked by `base.html`. No build step
   needed for the shared layer.
2. **Our `static/css/app.css`** — Tailwind v4, compiled from `static/src/app.css`, loaded into
   `{% block site_css %}`.

Both are **unlayered CSS**, so both already beat every Tailwind utility (unlayered wins over
`@layer` regardless of source order). The order only settles genuine selector collisions, and
there should be none: the package owns the chrome and `ds-*`, we own everything else.

Our Tailwind entry must contain:

```css
@import "tailwindcss";

@source "../../templates/**/*.html";
@source "../../build/kiam-ui/templates/**/*.html";   /* the one that bites */

@import "../../build/kiam-ui/css/theme.css";         /* token -> utility mapping */
```

`theme.css` is a Tailwind v4 `@theme` preset mapping tokens to brand utilities (`bg-page`,
`text-body`, `text-brand`, `text-faint`, `rounded-card`, `font-display`, …) **by `var()`
reference, never by copied hex** — so a token change upstream flows straight through. It is not a
standalone stylesheet: it does not import the tokens, and resolves them at runtime from
`kiam-ui.css`.

`base.html` sets `bg-page text-body font-sans antialiased` on `<body>`, so **those four
utilities must exist in our build** — which is exactly why the second `@source` line is not
optional. Missing it fails invisibly in dev (nothing is purged) and only in production.

`npm run build:css` runs `kiam_ui_vendor` first so the vendor step cannot be forgotten.

## 7. Gaps — what `kiam-ui` v1.0.1 does not give us

Recorded here as required by `CLAUDE.md`. **Nothing below is a reason to fork a packaged
component**; each is either configured around or built locally in `templates/components/`.

1. **The chrome is i18n-shaped; this project is English-only, LTR-only.**
   `base.html` calls `{% get_current_language %}` / `{% get_current_language_bidi %}`, the
   partials use `{% translate %}`, and `SHOW_LANGUAGE_SWITCHER` defaults to `True`.
   *Worked around:* `SHOW_LANGUAGE_SWITCHER = False` (so the switcher is never included and we
   never need `django.conf.urls.i18n`), and `django.template.context_processors.i18n` stays wired
   because the packaged templates load the tag library. `USE_I18N` stays `False` — the i18n
   template tags still resolve, they just return the single active language. **No `{% trans %}`
   tags, no locale dirs, no RTL work in this repo** (CLAUDE.md).

2. **The emergency disclaimer bar's copy is the *clinic's*, not the directory's.**
   The packaged copy says "*Please be advised that {SITE_NAME} is not an acute or emergency
   service…*", which is right in shape but says nothing about the practitioners being
   independent, and the crisis wording required by `docs/content-compliance.md` §7 (GP / 111 /
   999 / Samaritans 116 123) is not what it renders.
   *Worked around:* `DISCLAIMER_TEMPLATE` points at
   `templates/components/_disclaimer_bar_directory.html` — the supported extension point, which
   keeps the package's marquee, landmark, pause control and WCAG 2.2.2 behaviour. The §7 crisis
   line is rendered separately in the footer via `FOOTER["NOTE"]`.
   **`TODO(sign-off)` — Dr. Abbass on the crisis wording, CQC compliance lead on the
   independence sentence.**

3. **Fonts are loaded from Google Fonts by default.** `{% block fonts %}` emits `preconnect` +
   a stylesheet `<link>` to `fonts.googleapis.com`. That is a third-party request on every page
   before any consent decision, which sits badly with golden rule #4 and adds a render-blocking
   round trip against the `docs/seo.md` performance budget.
   *Not worked around in Phase 0* — noted so it is a deliberate decision, not an oversight. The
   fix is self-hosting the two families and overriding `{% block fonts %}`; it belongs upstream
   in `kiam-ui` (all three sites have the same problem) rather than as a local override here.
   **Raise as a kiam-ui issue.**

4. **The icon sprite has no directory-shaped glyphs.** No `map`, `filter`, `sliders-h`,
   `badge-check` or `map-pin-plus`. `VerifiedBadge` needs a distinct mark from
   `shield-check`, and `FilterSidebar` wants a filter glyph.
   *Worked around for now:* reuse `shield-check`, `pin`, `settings` and `search`. If a genuinely
   new glyph is needed in Phase 3/4, propose it upward — a sprite addition is a `minor` release
   and benefits all three sites.

5. **`KIAM_UI["URLS"]` is configuration with no consumer.** No packaged template reads it at
   v1.0.1. Cross-links to the main site have to go through `NAV_ITEMS` (with `external: True`)
   and `FOOTER["COLUMNS"]`.
   *Worked around:* we set `URLS` anyway — it is the obvious place for `docs/seo.md`'s
   deliberate cross-linking to read from — and reference it from our own templates.

6. **No page-layout or grid components.** The package ships `container` and `section` and stops
   there. Every layout in this repo is ours.

7. **No `docs/` ships with the package, and its own comments reference files that live in the
   main site repo** — `docs/accessibility-contrast.md`, `docs/design-system.md`,
   `docs/page-composition.md`. The contrast figures in §5 above were recovered from the CSS
   comments themselves, which is the only copy this repo can see. If the full contrast matrix is
   needed for the Phase 7 WCAG audit, it has to come from the main site repo or be re-measured.

8. **`kiam-ui` requires `Django>=5.2,<6.0`**, but this repo's `pyproject.toml` declared
   `Django>=5.1,<6.0`. Resolution succeeded (5.2.x satisfies both) but our floor was
   misleading. *Applied:* the floor is now `Django>=5.2,<6.0`, with a comment saying why.

9. **The CSS source directory ships inside the package's `static/` tree, and it breaks
   `collectstatic`.** `kiam_ui/static/kiam_ui/css/src/` is build input — `theme.css` is a
   Tailwind v4 preset that opens with `@import "tailwindcss"` and resolves its values at runtime
   from the compiled stylesheet. It is not a servable file. But because it sits under `static/`,
   `collectstatic` collects it, and `ManifestStaticFilesStorage` (the standard production choice,
   and what WhiteNoise recommends) post-processes every collected `.css` and tries to resolve
   each `@import`. `tailwindcss` is a package name, not a path, so the command dies:

   ```
   whitenoise.storage.MissingFileError: The file 'kiam_ui/css/src/tailwindcss'
   could not be found
   ```

   This hits **every** consumer using manifest static files, and it fails at deploy time rather
   than in development. Note the irony: `kiam_ui_vendor`'s own docstring explains that the vendor
   destination sits outside `static/` precisely so `collectstatic` cannot sweep it up — the same
   reasoning applies to the package's own `css/src/`, which was not moved.

   *Worked around:* `seo/management/commands/collectstatic.py` subclasses the command and adds
   `src` to the default ignore patterns, so it works without anyone remembering a flag. This
   requires `LOCAL_APPS` to precede `django.contrib.staticfiles` in `INSTALLED_APPS`, because
   Django resolves a management-command name collision in favour of the app listed *earlier* —
   see the comment in `config/settings/base.py`.
   **Raise as a kiam-ui issue:** ship `css/src/` outside the package's static tree (e.g. as
   package data at `kiam_ui/css_src/`), and `kiam_ui_vendor` copies from there instead. When
   that lands, the local override can be deleted.

`FilterSidebar`, `FilterGroup`, `PractitionerCard`, `VerifiedBadge`, `TagGroup`,
`ContactRevealPanel`, `CompletenessMeter`, `VerificationStatusPanel`) are built here, in
`templates/components/`, as plain `{% include %}` partials.

- **Compose from kiam-ui primitives.** A `PractitionerCard` is `cards/card.html` plus a
  `dir-practitioner` modifier class and a body slot — not a new card.
- **Follow the slot convention** (`*_template`), not a bespoke one.
- **Take `heading_level` as a parameter** wherever the component renders a heading.
- **Namespace classes `dir-*`.** Never redefine a `ds-*` or chrome class.
- **Reference tokens.** No hex, no font stacks, no spacing values in this repo's CSS.
- **Document parameters in a `{% comment %}` at the top of the file**, matching kiam-ui's style —
  that comment is what the next reader will trust.
- Propose a component upward to `kiam-ui` only when another site needs it.
